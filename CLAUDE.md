# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Data/research repo with a thin Astro front end for browsing it. It holds crawled YC (Y Combinator) company and founder data plus Korean-language analysis reports supporting a YC application, presented through a static site deployed to Vercel. Reports discuss the applying team only in generic terms (roles, backgrounds) — no personal names.

## Commands

- `npm run dev` — local dev server (Astro, HMR)
- `npm run build` — static build to `dist/` (what Vercel runs via `vercel.json`)
- `npm run preview` — serve the production build locally

No lint/test tooling configured.

## Structure

- `data/raw/`: raw data files (`yc_companies_all.{csv,json}`, `yc_founders_w25.{csv,json}`, `yc_founders_s24_w24.json`, `yc_idea_stage_analysis.json`) — the source of truth, edited directly. Not consumed by the site; reference-only.
- `data/overview/`: `*_overview.md` field/stats docs, one per raw dataset.
- `reports/`: Korean analysis reports (`.md`) — the source of truth, edited directly. Loaded via the `reports` content collection (`src/content.config.ts`, glob loader over `./reports`).
- `reports/en/`: hand-translated English versions, one file per Korean report, **same filename**. Loaded via the `reportsEn` collection (glob loader over `./reports/en`). These are real static translations, not machine-translated at runtime — there is no browser-translate widget in this site (an earlier Google Website Translator integration was replaced because it was unreliable on the deployed domain).
- `src/pages/index.astro` / `src/pages/en/index.astro`: Korean and English home pages.
- `src/pages/reports/[slug].astro`: renders each Korean report at `/reports/<filename-without-extension>/` from the `reports` collection.
- `src/pages/en/reports/[slug].astro`: renders each English report at `/en/reports/<filename-without-extension>/` from the `reportsEn` collection. Slugs must match between the two collections for the language-toggle links to resolve correctly (see below).
- `src/lib/reportMeta.ts`: hand-maintained metadata, **twice** — `reportMeta`/`groupOrder` for Korean (title/group/description), `reportMetaEn`/`groupOrderEn` for English. Both are keyed by the same report slug. **New reports must be added to both maps** or they won't appear in that language's sidebar nav (the page itself would still build and be reachable by direct URL if the corresponding `.md` file exists).
- `src/layouts/Base.astro`: the whole shell — sidebar nav (rendered from whichever `reportMeta`/`reportMetaEn` map matches the `lang` prop), GitHub link, light/dark/system theme toggle (persisted to `localStorage`, applied via `data-theme` on `<html>`), Korean/English toggle (plain link to the equivalent page under `/` or `/en/`, computed by stripping/adding the `/en` prefix from the current path), OG/Twitter meta tags (per-page `description`), and Astro View Transitions (`<ClientRouter />`). The sidebar's `transition:persist` key includes `lang` (`sidebar-${lang}`), so navigating between reports in the same language keeps the sidebar DOM in place, but switching language forces a fresh sidebar render in the new language.

**Adding or updating a report:** edit/add the Korean file in `reports/`, add its metadata to `reportMeta`/`groupOrder` in `reportMeta.ts`. If an English version exists or is added, it must live at `reports/en/<same filename>.md` with matching metadata in `reportMetaEn`/`groupOrderEn` — mismatched filenames between `reports/` and `reports/en/` will make the language toggle link to a 404 for that report. There is no requirement that every report have an English translation; reports without one simply won't appear in the English sidebar (their `/en/reports/<slug>/` page won't be generated by `getStaticPaths` since it's driven by whatever's actually in `reports/en/`).

There is no docs-mirroring step beyond the ko/en split above (an earlier Docsify-based `docs/` copy was removed in favor of this Astro site).

## Charts on the companies-report page

`reports/yc_companies_report.md` (and its English translation) render six interactive charts below the markdown content, in addition to — not instead of — the tables already in the `.md` source. This is the one place in the site with data-driven visuals; other reports are plain rendered markdown.

- `src/lib/companiesData.ts`: reads `data/raw/yc_companies_all.csv` (6,092 companies) and `data/raw/yc_ai_share_by_year.csv` at **build time** via `csv-parse`, using `process.cwd()`-relative paths (not `import.meta.url` — that breaks once Astro moves the compiled module under `dist/.prerender/`). Exports pre-aggregated arrays (`companiesByYear`, `industryDistribution`, `statusDistribution`, `aiShareByYear`, `recentBatches`, `teamSizeDistribution`) consumed directly by both `src/pages/reports/[slug].astro` and `src/pages/en/reports/[slug].astro`, gated behind `entry.id === "yc_companies_report"`.
- `data/raw/yc_ai_share_by_year.csv`: a companion dataset (year, total companies, AI-company count, AI share %) since the main `yc_companies_all.csv` doesn't have per-company AI classification as a flat column. Regenerated from the raw `tags` array on each company (from the [yc-oss/api](https://github.com/yc-oss/api) source), counting companies with YC's own official `"AI"` tag — this is YC's classification, not a keyword-derived guess, so treat it as the source of truth rather than re-deriving it differently.
- `src/components/LineChart.astro` / `src/components/BarChart.astro`: self-contained chart components (inline SVG, no chart library) with crosshair/hover tooltips, light/dark theming via the same CSS custom properties as the rest of the site, and `astro:page-load`-bound interactivity (idempotent init guarded by a `dataset.bound` flag, since View Transitions re-fire the event without a full reload).
- If `companiesData.ts`'s aggregation logic changes, sanity-check the output against the corresponding table already in `reports/yc_companies_report.md` — both are derived from the same `yc_companies_all.csv`, so they should match exactly.

## Data files

- `data/raw/yc_companies_all.csv` / `.json` — full YC company list (6,092 companies, Summer 2005–Winter 2027, 49 batches). Sourced from [yc-oss/api](https://github.com/yc-oss/api) (updated daily; this repo's snapshot is from 2026-07-29 — see "Updating this dataset" below for how to refresh it). Fields: name, batch, year, industry, one_liner, website, slug, team_size, status, url, long_description.
- `data/raw/yc_founders_w25.csv` / `.json` — Winter 2025 founders (321 people, 165 companies). Fields: company_name, founder_name, founder_title, founder_bio, founder_linkedin, founder_twitter. Crawled separately from `yc_companies_all.*` on 2026-07-22; not kept in sync with the yc-oss refresh.
- `data/raw/yc_founders_s24_w24.json` — Summer 2024 + Winter 2024 founders (566 companies, 1,075 founders), nested per-company with a `founders` array.
- `data/raw/yc_idea_stage_analysis.json` — supporting data for the idea-stage tracking report.
- `data/raw/yc_ai_share_by_year.csv` — year, total companies, AI companies, AI share % (2005–2027). Backs the AI-share chart on the companies-report page; see "Charts on the companies-report page" above for how it's derived.

## Updating this dataset

`yc_companies_all.csv`/`.json` and `yc_ai_share_by_year.csv` can be refreshed from [yc-oss/api](https://github.com/yc-oss/api)'s daily-updated `https://yc-oss.github.io/api/companies/all.json` endpoint — fetch it, drop the single `"Unspecified"`-batch `"Y Combinator"` placeholder entry, and remap fields to this repo's column set (`name`, `batch`, `year` — parsed from the last token of `batch` — `industry`, `one_liner`, `website`, `slug`, `team_size`, `status`, `url`, `long_description`). Recompute `yc_ai_share_by_year.csv` by grouping on that same `year` and counting entries whose `tags` array contains `"AI"`. After regenerating, re-run the aggregation math (`companiesData.ts`'s logic, or equivalent ad-hoc scripting) and update the hardcoded tables in `reports/yc_companies_report.md` (+ its `en/` translation) and `data/overview/yc_companies_all_overview.md` to match — those are static snapshots, not live-computed, so they drift from the CSV unless refreshed by hand each time.

Each raw dataset has a matching `data/overview/*_overview.md` describing its fields/stats/samples — check those before writing code that parses the raw files.

## Reports

Reports live in `reports/`, in Korean, layered (matches the `group` field in `src/lib/reportMeta.ts`):
- 기본 분석 (base analysis, data-driven — direct aggregation over the raw datasets, no subjective strategy/recommendation content): `yc_companies_report.md`, `yc_student_founders_report.md`, `yc_report_ai_b2b.md`, `yc_report_asia.md`, `yc_founders_career_analysis.md`.
- 심화 리서치 (deeper research, includes interpretive/strategic content): `yc_application_strategy.md`, `yc_interview_patterns.md`, `yc_korean_founders_deep_dive.md`, `yc_idea_stage_companies_tracking.md`, `yc_demo_day_investment_analysis.md`, `yc_competitive_landscape.md`, `yc_application_qa_analysis.md`, `yc_ai_b2b_gaps_analysis.md`, `yc_ai_b2b_complete_list.md`.
- 데이터 (data, raw listings rather than analysis): `yc_recent_batches_raw.md`, `yc_founders_career_raw.md`.

`README.md` (root) is a human-facing index describing recommended reading order and key insights — update it when adding a new report. It is documentation only, not read by the site.

## Conventions

- Written in Korean; keep new reports/edits in Korean to match existing content unless told otherwise.
- Data source note: `yc_companies_all.*` and `yc_ai_share_by_year.csv` reflect a 2026-07-29 snapshot of [yc-oss/api](https://github.com/yc-oss/api); the founder datasets (`yc_founders_*`) reflect a 2026-07-22 crawl of ycombinator.com — mention/preserve whichever provenance note is relevant when generating new reports from that data.
